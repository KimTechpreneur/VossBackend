# Folders Management API Documentation

This document outlines the API endpoints required for the Folders Management feature, enabling seamless integration with the existing frontend.

---

## 1. Data Models

### 1.1. `FolderTransferStatus`
Represents the possible transfer statuses of a folder.

```typescript
type FolderTransferStatus = 'Not Started' | 'In Transit' | 'Delivered' | 'Overdue' | 'Pending' | 'Cancelled';
```

### 1.2. `FolderService`
Represents the services/departments associated with a folder.

```typescript
type FolderService = 'Finance Department' | 'Admissions Office' | 'Registrar' | 'Human Resources' | 'Academic Affairs' | 'Student Services';
```

### 1.3. `FolderPriority`
Represents the priority levels for a folder.

```typescript
type FolderPriority = 'urgent' | 'normal' | 'low' | 'confidential';
```

### 1.4. `Folder` (List View)
Represents a folder in the system, primarily for list views.

```typescript
interface Folder {
  id: string; // Unique identifier for the folder (e.g., VOSS-YYYY-XXXX)
  subject: string; // The main subject or title of the folder
  service: FolderService; // The service/department the folder belongs to
  fileCount: number; // Number of files attached to the folder
  transferStatus: FolderTransferStatus; // Current transfer status
  createdBy: { id: string; name: string; department?: string; initials?: string; avatarColor?: string }; // Basic info of the user who created it
  dateCreated: string; // ISO 8601 timestamp of creation
  isSigned: boolean; // Indicates if the folder requires signature and is signed
  currentLocation: string; // Current location/office of the folder
}
```

### 1.5. `FolderFilters`
Represents the filtering and sorting parameters for fetching folders.

```typescript
interface FolderFilters {
  searchQuery: string; // General search term for folder ID, subject, service, or createdBy name
  transferStatus: FolderTransferStatus | 'all'; // Filter by transfer status
  service: FolderService | 'all'; // Filter by associated service
  createdBy: string; // Filter by the ID of the user who created the folder
  currentLocation: string; // Filter by the current location/office of the folder
  dateRangeFrom?: string; // ISO 8601 timestamp for start of creation date range
  dateRangeTo?: string; // ISO 8601 timestamp for end of creation date range
  fileCountMin?: number; // Minimum number of files
  fileCountMax?: number; // Maximum number of files
  signatureStatus: 'signed' | 'unsigned' | 'all'; // Filter by signature status
  priority: FolderPriority | 'all'; // Filter by priority tag
  // Backend should also support:
  // sortBy: 'subject' | 'service' | 'fileCount' | 'transferStatus' | 'createdBy.name' | 'dateCreated'; // Field to sort by
  // sortOrder: 'asc' | 'desc'; // Sort direction
  // page: number; // Current page number for pagination
  // limit: number; // Number of items per page for pagination
}
```

### 1.6. `FolderFile`
Represents a file attached to a folder.

```typescript
interface FolderFile {
  id: string; // Unique identifier for the file
  name: string; // Filename
  type: string; // File type (e.g., PDF, DOCX)
  size: string; // File size (e.g., "2.4MB")
  uploadedBy: string; // Name of the user who uploaded it
  dateAdded: string; // ISO 8601 timestamp of when the file was added
  // For backend, size could be in bytes (number) and dateAdded as datetime object
}
```

### 1.7. `NewFolderData`
Represents the data structure used for creating a new folder, including initial metadata and files.

```typescript
interface NewFolderData {
  subject: string;
  service: FolderService;
  priorityTag: FolderPriority;
  comment?: string; // Optional: General comment for the folder
  requiresSignature: boolean;
  forwardingComment?: string; // Optional: Comment for forwarding/routing
  files: Array<{ name: string; type: string; size: number; base64Content?: string; /* or file upload ID */ }>; // Files to be uploaded with the folder
  autoGenerateFileNumbers: boolean; // Indicates if file numbers should be auto-generated by backend
  // For backend, actual file content/upload mechanism would be handled separately (e.g., multipart form data, pre-signed URLs)
}
```

### 1.8. `FolderMetadata` (Detailed View)
Represents the detailed metadata for a single folder.

```typescript
interface FolderMetadata {
  id: string;
  title: string; // Can be derived from subject
  subject: string;
  service: FolderService;
  comment?: string;
  priorityTag?: FolderPriority;
  requiresSignature: boolean;
  forwardingComment?: string;
  createdBy: { name: string; department?: string; id: string }; // More complete creator info
  createdAt: string; // ISO 8601 timestamp
  currentOffice: {
    name: string;
    step: number;
    totalSteps: number;
  }; // Current location in a workflow/routing process
  status: {
    inTransit: boolean;
    overdue: boolean;
    // Other relevant status flags
  };
  fileCount: number;
  // Potentially include last modified date/user, etc.
}
```

## 2. API Endpoints

All endpoints should be prefixed with `/api/v1/folders`.

### 2.1. Get All Folders

*   **HTTP Method:** `GET`
*   **Endpoint URL:** `/api/v1/folders`
*   **Description:** Retrieves a list of all folders, with support for searching, filtering, and pagination.
*   **Query Parameters:**
    *   `searchQuery` (string, optional): Search term for folder ID, subject, service, or createdBy name.
    *   `transferStatus` (string, optional): Filter by `transferStatus`.
    *   `service` (string, optional): Filter by `service`.
    *   `createdBy` (string, optional): Filter by creator's user ID.
    *   `currentLocation` (string, optional): Filter by current office location.
    *   `dateRangeFrom` (string, optional): Start date (ISO 8601) for `dateCreated` filter.
    *   `dateRangeTo` (string, optional): End date (ISO 8601) for `dateCreated` filter.
    *   `fileCountMin` (number, optional): Minimum `fileCount`.
    *   `fileCountMax` (number, optional): Maximum `fileCount`.
    *   `signatureStatus` (string, optional): Filter by `isSigned` (`signed`, `unsigned`). Default: `all`.
    *   `priority` (string, optional): Filter by `priorityTag` (`urgent`, `normal`, `low`, `confidential`). Default: `all`.
    *   `sortBy` (string, optional): Field to sort by (`subject`, `service`, `fileCount`, `transferStatus`, `createdBy.name`, `dateCreated`). Default: `dateCreated`.
    *   `sortOrder` (string, optional): Sort direction (`asc` or `desc`). Default: `desc`.
    *   `page` (number, optional): Current page number (1-indexed). Default: `1`.
    *   `limit` (number, optional): Number of folders per page. Default: `10` (or a sensible backend default).
*   **Success Response:** `200 OK`
    ```json
    {
      "folders": [
        {
          "id": "VOSS-2023-0048",
          "subject": "Annual Financial Audit Reports",
          "service": "Finance Department",
          "fileCount": 5,
          "transferStatus": "In Transit",
          "createdBy": { "id": "user-1", "name": "John Doe", "department": "Finance" },
          "dateCreated": "2023-05-24T10:00:00Z",
          "isSigned": true,
          "currentLocation": "Admissions Office"
        }
        // ... more folders
      ],
      "totalItems": 100,
      "totalPages": 10,
      "currentPage": 1,
      "itemsPerPage": 10
    }
    ```
*   **Error Responses:**
    *   `500 Internal Server Error` (Generic error)
*   **Authentication/Authorization:** Requires authenticated user. Folder viewing permissions.

### 2.2. Get Single Folder by ID (Detailed View)

*   **HTTP Method:** `GET`
*   **Endpoint URL:** `/api/v1/folders/{id}`
*   **Description:** Retrieves detailed information for a single folder by its ID, including its metadata and associated files.
*   **Path Parameters:**
    *   `id` (string, required): The unique identifier of the folder.
*   **Success Response:** `200 OK`
    ```json
    {
      "id": "VOSS-2023-0048",
      "title": "Annual Financial Audit Reports",
      "subject": "Annual Financial Audit Reports",
      "service": "Finance Department",
      "comment": "Important financial documents for annual audit.",
      "priorityTag": "urgent",
      "requiresSignature": true,
      "forwardingComment": "Please review and process.",
      "createdBy": { "id": "user-1", "name": "John Doe", "department": "Finance" },
      "createdAt": "2023-05-24T10:00:00Z",
      "currentOffice": {
        "name": "Admissions Office",
        "step": 2,
        "totalSteps": 4
      },
      "status": {
        "inTransit": true,
        "overdue": false
      },
      "fileCount": 5,
      "files": [
        {
          "id": "file-1",
          "name": "financial_report_Q1.pdf",
          "type": "PDF",
          "size": "2.4MB",
          "uploadedBy": "John Doe",
          "dateAdded": "2023-05-24T10:15:00Z"
        },
        // ... more files
      ]
    }
    ```
*   **Error Responses:**
    *   `404 Not Found` (If folder with `id` does not exist)
    *   `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user. Folder viewing permissions.

### 2.3. Create New Folder

*   **HTTP Method:** `POST`
*   **Endpoint URL:** `/api/v1/folders`
*   **Description:** Creates a new folder with its initial metadata and attached files.
*   **Request Body:** (`multipart/form-data` if files are directly uploaded, or `application/json` with file IDs/references)
    ```json
    {
      "subject": "New Project Documentation",
      "service": "Academic Affairs",
      "priorityTag": "normal",
      "comment": "Initial documents for the new research project.",
      "requiresSignature": false,
      "forwardingComment": "To be reviewed by department head.",
      "files": [ // Example for if files are sent as array of objects with content/references
        { "name": "project_plan.pdf", "type": "application/pdf", "size": 102400, "content": "base64encodedstring..." },
        { "name": "research_proposal.docx", "type": "application/vnd.openxmlformats-officedocument.wordprocessingml.document", "size": 51200 }
      ],
      "autoGenerateFileNumbers": true
    }
    ```
    *   **Note:** The actual file upload mechanism needs careful consideration (e.g., direct file upload in multipart form, or separate endpoint for file uploads and then referencing them by ID).
*   **Success Response:** `201 Created`
    ```json
    {
      "id": "VOSS-2024-0101",
      "subject": "New Project Documentation",
      "service": "Academic Affairs",
      "fileCount": 2,
      "transferStatus": "Not Started",
      "createdBy": { "id": "user-current", "name": "Current User", "department": "IT" },
      "dateCreated": "2024-05-26T12:00:00Z",
      "isSigned": false,
      "currentLocation": "Academic Affairs"
    }
    ```
*   **Error Responses:**
    *   `400 Bad Request` (Invalid input, e.g., missing required fields, invalid file data)
    *   `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to create folders.

### 2.4. Update Existing Folder Metadata

*   **HTTP Method:** `PATCH`
*   **Endpoint URL:** `/api/v1/folders/{id}`
*   **Description:** Updates the metadata (e.g., subject, comment, priority) of an existing folder.
*   **Path Parameters:**
    *   `id` (string, required): The unique identifier of the folder to update.
*   **Request Body:** (`application/json`)
    *   Fields are optional. Only send fields that need to be updated.
    ```json
    {
      "subject": "Revised Project Documentation",
      "comment": "Updated notes after team meeting.",
      "priorityTag": "urgent",
      "requiresSignature": true,
      "forwardingComment": "Urgent review required."
    }
    ```
*   **Success Response:** `200 OK`
    ```json
    {
      "id": "VOSS-2023-0048",
      "subject": "Revised Project Documentation",
      // ... other updated fields
    }
    ```
*   **Error Responses:**
    *   `400 Bad Request` (Invalid input)
    *   `404 Not Found` (If folder with `id` does not exist)
    *   `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to edit folders.

### 2.5. Delete Folder

*   **HTTP Method:** `DELETE`
*   **Endpoint URL:** `/api/v1/folders/{id}`
*   **Description:** Deletes a folder by its ID. This should ideally also handle associated files.
*   **Path Parameters:**
    *   `id` (string, required): The unique identifier of the folder to delete.
*   **Success Response:** `204 No Content` (No response body)
*   **Error Responses:**
    *   `404 Not Found` (If folder with `id` does not exist)
    *   `403 Forbidden` (If the folder is in transit, has ongoing processes, or current user lacks permission)
    *   `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to delete folders.

### 2.6. Manage Folder Files

#### 2.6.1. Add File(s) to Folder
*   **HTTP Method:** `POST`
*   **Endpoint URL:** `/api/v1/folders/{id}/files`
*   **Description:** Uploads and attaches one or more files to an existing folder.
*   **Path Parameters:**
    *   `id` (string, required): The unique identifier of the folder.
*   **Request Body:** (`multipart/form-data` for file uploads)
    *   Each file would be sent as a file part.
    *   Optional: `autoGenerateFileNumbers` (boolean): If file numbers should be auto-generated for these new files.
*   **Success Response:** `200 OK` (or `201 Created` for each file)
    ```json
    {
      "message": "Files uploaded successfully",
      "newFiles": [
        { "id": "new-file-1", "name": "document.pdf", "size": "1.5MB" }
      ]
    }
    ```
*   **Error Responses:** `400 Bad Request`, `404 Not Found`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to add files to folders.

#### 2.6.2. Remove File from Folder
*   **HTTP Method:** `DELETE`
*   **Endpoint URL:** `/api/v1/folders/{folderId}/files/{fileId}`
*   **Description:** Removes a specific file from a folder.
*   **Path Parameters:**
    *   `folderId` (string, required): The unique identifier of the folder.
    *   `fileId` (string, required): The unique identifier of the file to remove.
*   **Success Response:** `204 No Content`
*   **Error Responses:** `404 Not Found`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to remove files from folders.

#### 2.6.3. Download File from Folder
*   **HTTP Method:** `GET`
*   **Endpoint URL:** `/api/v1/folders/{folderId}/files/{fileId}/download`
*   **Description:** Downloads a specific file from a folder.
*   **Path Parameters:**
    *   `folderId` (string, required): The unique identifier of the folder.
    *   `fileId` (string, required): The unique identifier of the file to download.
*   **Success Response:** `200 OK` with `Content-Type` header set to the file's MIME type. The response body will be the file content.
*   **Error Responses:** `404 Not Found`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with permissions to download files from folders.

### 2.7. Bulk Actions (Optional but Recommended)

#### 2.7.1. Archive Multiple Folders

*   **HTTP Method:** `POST`
*   **Endpoint URL:** `/api/v1/folders/bulk/archive`
*   **Description:** Archives a list of folders.
*   **Request Body:** (`application/json`)
    ```json
    {
      "folderIds": ["VOSS-2023-0001", "VOSS-2023-0002"]
    }
    ```
*   **Success Response:** `200 OK` or `204 No Content`
    ```json
    {
      "message": "Selected folders archived successfully."
    }
    ```
*   **Error Responses:** `400 Bad Request`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with bulk folder management permissions.

#### 2.7.2. Assign Multiple Folders to Unit/Location

*   **HTTP Method:** `POST` or `PATCH`
*   **Endpoint URL:** `/api/v1/folders/bulk/assign-location`
*   **Description:** Assigns a new current location to a list of folders.
*   **Request Body:** (`application/json`)
    ```json
    {
      "folderIds": ["VOSS-2023-0001", "VOSS-2023-0002"],
      "newLocationId": "office-xyz" // ID of the new office/unit
    }
    ```
*   **Success Response:** `200 OK`
    ```json
    {
      "message": "Selected folders assigned to new location successfully."
    }
    ```
*   **Error Responses:** `400 Bad Request`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with bulk folder management permissions.

#### 2.7.3. Delete Multiple Folders

*   **HTTP Method:** `POST` or `DELETE`
*   **Endpoint URL:** `/api/v1/folders/bulk/delete`
*   **Description:** Deletes multiple folders by their IDs.
*   **Request Body:** (`application/json`)
    ```json
    {
      "folderIds": ["VOSS-2023-0001", "VOSS-2023-0002"]
    }
    ```
*   **Success Response:** `204 No Content`
*   **Error Responses:** `400 Bad Request`, `403 Forbidden`, `500 Internal Server Error`
*   **Authentication/Authorization:** Requires authenticated user with bulk folder deletion permissions.

## 3. General Considerations for Backend (Django)

*   **Model Relationships:** Define Django models for `Folder` and `FolderFile`. `Folder` should have a `ForeignKey` to `User` for `createdBy` and potentially `Office` for `currentLocation`. `FolderFile` should have a `ForeignKey` to `Folder`.
*   **File Storage:** Implement robust file storage (e.g., Django's `FileField` with a suitable backend like local filesystem or cloud storage). Consider how file content will be handled during creation (e.g., direct upload vs. pre-signed URLs).
*   **Unique Constraints:** Ensure `id` (folder ID) is unique for folders.
*   **Referential Integrity:** When deleting a folder, ensure all associated files are also handled (e.g., deleted from storage).
*   **Workflow/Routing Status:** The `currentOffice`, `step`, and `totalSteps` imply a workflow or routing system. This might require additional models or logic in the backend to manage the progression of folders.
*   **Signature Management:** The `requiresSignature` and `isSigned` fields indicate a digital signature workflow. The backend will need to support the mechanisms for requesting and recording signatures.
*   **Auto-generated IDs/Numbers:** Implement logic for generating unique folder IDs (e.g., `VOSS-YYYY-XXXX`) and auto-generating file numbers if `autoGenerateFileNumbers` is true.
*   **Filtering, Sorting, Pagination:** Utilize Django ORM and Django REST Framework features for efficient data handling.
*   **Error Handling:** Maintain consistent JSON error responses.
*   **API Versioning:** Continue using `/api/v1/`.
*   **Audit Logging:** Log significant folder and file actions (creation, updates, deletions, file additions/removals, status changes).
